# Feature specification

## Outcome

Describe the observable result for the user or system.

## Actors and entry point

Identify who starts the flow, from where, and under which preconditions.

## Functional requirements

Number each required behavior. Include success, invalid input, loading, offline, stale, partial, retry, cancellation, duplicate delivery, and incompatible-version behavior when relevant.

## Acceptance scenarios

Write observable Given/When/Then scenarios without prescribing implementation.

## Non-goals

List adjacent behavior intentionally excluded from this slice.

## Supported targets

Name the platforms, source-set scope, backend involvement, and required device topology.

## Safety, privacy, authorization, and compatibility

Record applicable constraints or state explicitly that each category is not affected and why.

## Evidence required

Name the minimum evidence level required for each acceptance scenario and target.
